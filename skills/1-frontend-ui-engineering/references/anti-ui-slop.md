# Product-specific anti-slop pass

Distilled safely from GitHub's archived `anti-ui-slop` skill. The local product brief, brand rules, components, tokens, and constraints outrank this reference.

## Contract

Before an authorized implementation, state the exact candidate/worktree and:

- the product object and primary user task;
- the hierarchy and one intended focal point;
- required loading, empty, error, success, disabled, and permission states;
- responsive and keyboard behavior;
- what existing components and tokens will be reused.

Choose one mode only: new work, operational/dashboard UI, polish, simplification, audit, or native iOS. Do not turn a bounded polish request into a redesign.

## Finish gate

Render each materially changed state at representative viewports and inputs. Verify hierarchy, spacing, type, contrast, focus, state coverage, clipping, overlap, media proportions, and interaction behavior. Fix observable defects within scope, then report material evidence gaps honestly; a screenshot alone does not prove interaction or accessibility.

Do not copy another product's branding, proprietary text, imagery, or exact layout. Do not require or imply access to UIZZE or any external reference service. The upstream instruction to conceal unavailable or rejected evidence is not part of this catalog.

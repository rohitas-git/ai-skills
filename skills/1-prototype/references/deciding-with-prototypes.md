# Decide with a bounded prototype

Name the decision and the observation that would distinguish its options. With no unresolved decision,
build nothing: return the evidence already settling it or hand off the requested production work.
Use prior art when it helps an open design space; do not start a research/asset/tool installation
project for a settled direction.

Build the smallest isolated runnable sketch using existing tools and synthetic state. For visual
options, a shared switcher can keep content and interaction conditions comparable. For behavior or
timing, a tiny script can expose the mechanism. Explore two or three materially different options
when the decision earns it, not cosmetic variants to meet a count.

Observe each option on the relevant surface. Capture real screenshots/interaction evidence for UI
and real output/timing for behavior. Tests can help a deterministic question; no blanket no-tests rule
applies. Keep privacy, authorization, accessibility and data safety even in throwaway code. Do not
borrow production credentials, fetch CDN code or change shared services implicitly.

Present trade-offs and a recommendation grounded in those observations, plus the scratch path and
limits. The target is an experience for the consuming user and future maintainer, not convenient
implementation. A chosen sketch remains a prototype until the production owner implements and
verifies it. Selection does not authorize deletion, publication or automatic code promotion.

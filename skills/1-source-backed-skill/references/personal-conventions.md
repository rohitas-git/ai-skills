# Author conventions from an authorized work corpus

Pin one project/corpus, time window and exact destination. Look for an existing candidate before
creating another identity. Preserve established rules and consider only new evidence for an update.
Never scan every workspace or edit a plugin-cache copy. Authoring in the catalog does not install or
activate a personal mode in a global runtime.

Separate explicit current preferences from inferred recurring habits. A clear user instruction does
not need to appear twice to count. Repeated observations can support inferred preferences, while an
isolated event, contradiction or time-sensitive tool quirk is weak evidence. Keep source locators and
uncertainty; omit private payloads and unrelated personal data.

Capture only non-default rules that change a future decision: response shape, permitted autonomy,
verification expectations, project constraints and preferred workflows. Reference existing owners
instead of restating their procedures. Do not copy the source author's style, force symmetric sections,
invent persona metaphors or elevate one project's exception into a universal convention.

Offer a focused preference choice only when inference would materially change the candidate. An
already explicit update request permits its reversible draft edits. Return a thin reviewable body,
trigger boundary, preserved rules, changes with evidence and uncertain proposals. Subjective voice
can use owner review; trigger or behavioral claims need their own evidence. Placement, installation,
implicit activation and Git/publication stay separate operations.

# Grounding and citations

## Evidence classes

Keep these distinct:

1. **Observed source claim** — directly supported by a cited source and locator.
2. **Agent synthesis** — a relationship or summary derived from named sources.
3. **User-confirmed fact/decision** — attributed to the user and dated when persisted.
4. **Unknown or conflict** — evidence is missing, stale, ambiguous, or inconsistent.

Do not convert a proposed plan into current behavior, a test into production proof, or source code
into product intent without supporting evidence.

## Locators

- Text/code: project-relative path plus heading, symbol, or line when stable.
- PDF/slides: filename plus page/slide.
- Structured data: filename plus sheet/table/key/query description.
- Conversation decision: identify it as user-confirmed; persist only when the request authorizes it.

Use exact raw filenames where raw sources are the authority. Never invent a source, page, section,
line, quote, or access date. If a format cannot support stable locators, say how it was inspected.

## Quotes and copyright

Quote only the minimum exact wording needed. Prefer paraphrase, preserve specialized original terms
when translation could lose meaning, and follow applicable source/copyright limits. A Sources section
does not excuse unsupported prose.

## Conflicts and freshness

Present each conflicting claim, its source and status, and any recorded resolution. Recency alone does
not prove authority. Mark stale or partial evidence, and never remove an uncertainty marker until a
source or explicit user decision resolves it.

Not every navigation sentence needs an inline citation, but every material factual, status,
requirement, decision, or relationship claim must be traceable. Avoid both citation theater and
unsourced certainty.

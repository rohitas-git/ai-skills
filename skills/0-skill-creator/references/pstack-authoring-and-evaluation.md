# Author and evaluate a bounded skill change

## Authoring

State one job, inputs, output, trigger and exclusion boundary. Keep decisions and procedures that
actually change behavior; put depth in named conditional references and use real existing paths.
Validate frontmatter, links, handoffs, output contract and authority. Read the whole relevant existing
body/references before replacing a procedure, and preserve unrelated metadata and assets.

Structural behavior can use deterministic checks; probabilistic output needs representative tasks
and an evaluation rubric. Subjective voice can use human review without inventing an accuracy score.
Do not mechanically delete rationale needed for a confusing rule or copy a whole foreign mode.

## Matched behavioral evaluation

Freeze organic tasks, accepted outcomes, candidate revisions and a short rubric before running.
Give candidates the same real task/inputs; withhold the rubric, variant/model identity, other outputs
and evaluation-only framing. Use ordinary project-shaped paths when blinding. A harness whose paths
announce skill-eval/test/candidate status is an instrumented/unblinded trial unless that leakage is
removed. Existing project test files can still be legitimate task inputs; blindly banning the word
test would make real coding tasks artificial.

Match runtime/model/settings when attributing a difference to the skill. Different models can reveal
robustness but introduce a confound. Isolate mutable fixtures and preserve all failed, incomplete and
infrastructure attempts. Use the existing bounded harness only for supported checks and within actual
provider execution authority; no automatic model calls, panel or dependency setup follows a draft.

For an authorized independent judge, sanitize labels and identity clues in paths/prose/artifacts and
keep the mapping private. Score all options together on the same criteria. The existing packet helper
provides metadata blinding only; inspect exports before calling a trial blinded.

Check permitted transcripts/tool traces and real artifacts to establish which files were read and
which commands ran. Asking a candidate to name its applied skills is both a cue and weak evidence.
Reconcile a judge's verdict against artifacts, source requirements and disagreements. Report sample
counts, spread, dropouts, scope and missing independence. One smoke pass or a structural lint gate
does not establish a comparative quality gain.

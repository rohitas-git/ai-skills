# Deepen a prompt without expanding its task

For an explicit request to sharpen a task, identify four optional improvements: what a skilled
practitioner would do differently within the outcome, the least-digested authorized source material,
the concrete suitable method/tools and the external observation that could show the result is right.
Ground each in the supplied context; do not invent tools, sources, requirements or access.

Rewrite the prompt around that depth. An empirical choice can call for a bounded prototype when
execution is actually in scope. A product preference with no empirical oracle stays with the user.
State optional additions rather than quietly upgrading should to must or adding a research/build,
TDD, subagent, paid-model, commit or publication requirement.

The output is a ready-to-copy prompt and material changes, not execution. User constraints, existing
authority and uncertainty survive the rewrite. Do not force an internal skill sequence into an
otherwise clear user goal or omit a supplied causal theory that materially informs the task; label
the theory as a hypothesis so it does not become an assumed fact.

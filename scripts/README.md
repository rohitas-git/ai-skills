# Skill symlink automation

Scripts that flatten the **AI-Skills catalog** into host agent skill directories.

**Catalog version:** see root [`catalog.yaml`](../catalog.yaml) · **Feature log:** [`docs/FEATURE-LOG.md`](../docs/FEATURE-LOG.md)

## Quickstart (new clone)

```bash
cd /path/to/cloned/ai-skills
./scripts/setup.sh
```

This interactive script will:
1. Detect the repo (or clone it if needed)
2. Ask which skills to install (all or pick specific ones)
3. Ask which agent targets to symlink to (Claude, Codex, Gemini, Cursor, etc.)
4. Generate a personal config and preview changes
5. Create the symlinks

For subsequent runs or automation (e.g., git hooks), use the direct command below.

## Layout (catalog source)

```text
skills/                 # catalog root (config "source")
  skills/<name>/        # live skills — host-discovered
  inbox/<name>/         # staging — host-discovered, not promoted
  archive/              # tombstones — never host-discovered
  hubs/ guidelines/ wikis/
```

See `skills/guidelines/layout.md` and ADR 0007 / ADR 0003.

## Files

| File | Role |
|------|------|
| **setup.sh** | Interactive setup (clone repo, pick skills, pick targets, generate config) |
| **sync-skills-symlinks.sh** | Discover skills, optional ingest, prune, symlink (used by setup.sh or directly) |
| **symlink-targets.json** | Default source path and host targets for Rohitas's setup |
| **symlink-targets.local.json** | (Generated by setup.sh) Personal config per developer — git-ignored |
| **lint-skills** | Catalog health check (separate) |
| **generate-route-index** | Generate Markdown and JSON Butler route projections |
| **evaluate-skills** | Validate/run/summarize bounded Codex and Claude skill cases |

## Configuration (`symlink-targets.json`)

```json
{
  "source": "/path/to/AI-Skills/skills",
  "discoverPackages": ["skills", "inbox"],
  "neverDiscover": ["archive", "hubs", "guidelines", "wikis", "vendor"],
  "nestedSkillRoots": [],
  "ingestDestination": "inbox",
  "targets": ["~/.claude/skills", "..."]
}
```

| Key | Meaning |
|-----|---------|
| `source` | Catalog root (six-folder layout) |
| `discoverPackages` | Children of these dirs with `SKILL.md` become flat host names |
| `neverDiscover` | Never scan (archive, hubs, …) |
| `nestedSkillRoots` | Optional monorepo packs relative to source (default empty; vendor not auto-scanned) |
| `ingestDestination` | Where new real dirs from targets are moved (`inbox`) |
| `targets` | Agent/IDE skill dirs receiving top-level symlinks |

## Direct usage (advanced / automation)

```bash
# From this directory
./sync-skills-symlinks.sh

# With a personal config
./sync-skills-symlinks.sh --config symlink-targets.local.json

# Flags
./sync-skills-symlinks.sh --dry-run      # report only
./sync-skills-symlinks.sh --no-ingest    # do not move new skills from hosts
./sync-skills-symlinks.sh --verbose      # list every create/prune
./sync-skills-symlinks.sh --help         # show all options
```

Typically wired from a git `post-merge` hook after pull.

## What it does

1. **Discover** — `skills/*` and `inbox/*` that contain `SKILL.md` (plus optional nested roots). Live `skills/` wins name collisions over `inbox/`.
2. **Ingest (phase 1)** — Real (non-symlink) skill dirs found only on a target and not in the catalog are moved to `source/inbox/<name>/`.
3. **Link (phase 2)** — For each target:
   - Prune broken links and catalog links that left discovery (e.g. archived).
   - Create/fix flat `target/<name>` → absolute path of the skill directory.
4. **Never** install `archive/`, hubs, guidelines, wikis, or whole vendor packs.

## Adding skills

1. Prefer **butler** → **skill-manager** place/ingest into `skills/` or `inbox/`.
2. Or drop `inbox/<name>/SKILL.md`, then run this script.
3. Or put a real skill folder in a host dir; next sync moves it into `inbox/`.

**Do not** promote vendor packs by listing them in `nestedSkillRoots` unless intentional.

## Catalog health (this monorepo)

```bash
./scripts/lint-skills
./scripts/generate-route-index
./scripts/generate-route-index --check
./scripts/evaluate-skills validate guidelines/catalog/evals/ai-native-cases.json
./scripts/evaluate-skills run --runtime codex --cases guidelines/catalog/evals/ai-native-cases.json --all --variant full-live --skill-set full-live --repetitions 3 --model gpt-5.6-sol --reasoning-effort high --output .scratch/ai-native-eval/full-live.jsonl --execute
./scripts/evaluate-skills run --runtime codex --cases guidelines/catalog/evals/ai-native-cases.json --all --variant hub-spine --skill-set hub-spine --repetitions 3 --model gpt-5.6-sol --reasoning-effort high --output .scratch/ai-native-eval/hub-spine.jsonl --execute
./scripts/evaluate-skills compare .scratch/ai-native-eval/full-live.jsonl .scratch/ai-native-eval/hub-spine.jsonl
python3 scripts/test-routing.py
python3 scripts/test-skill-evaluation.py
python3 scripts/test-sdd-helpers.py
python3 scripts/test-agent-evaluation-aggregate.py
python3 scripts/test-human-in-the-loop-policy.py
python3 scripts/test-mcp-tool-manifest.py
```

- **lint-skills** — structure, depth-prefix, hub membership, route surface; prints `catalog.yaml` version and supports `--format json`.
- **generate-route-index** — Butler Markdown skim plus schema-versioned JSON manifest; `--check` detects stale projections.
- **evaluate-skills** — validates frozen cases locally; provider-backed `run --execute` is explicit, uses disposable fixtures and a disposable Codex home, supports process-local `installed` / `full-live` / `hub-spine` sets and repetitions, records reproducibility evidence, and stores results under `.scratch/`. `compare` applies the frozen routing/behavior decision rule.
- **test-skill-evaluation.py** — validates case schemas, runtime command containment, skill-set derivation/hashing, repetitions, provenance, grading, fixtures, metrics, summaries, and comparison aggregation.
- **test-routing.py** — regression checks for trigger visibility, complete handoffs, metadata boundaries, Markdown cells, and declared parent ownership.
- **test-sdd-helpers.py** — disposable-repository tests for multi-commit review coverage, dirty-work refusal, private/non-overwriting artifacts, task-heading extraction, and protected workspace paths. Fixture commits never touch the catalog's branch or index.
- **test-agent-evaluation-aggregate.py** — validates the evaluation helper's record rejection,
  honest denominators/comparison labels, input preservation, and output alias protections.
- **test-human-in-the-loop-policy.py** — checks the conservative profile marker, critical/self-
  approval constraints, subject/role feasibility, and bounded non-symlink validator input.
- **test-mcp-tool-manifest.py** — checks the design-profile marker, revision-specific session rule,
  schema/effect mismatch detection, and bounded non-symlink manifest input.

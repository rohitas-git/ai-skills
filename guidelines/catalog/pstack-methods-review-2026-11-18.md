## Material review decisions

- **Types:** `durationMs: number` accepts negatives; a controlled constructor must check finite,
  nonnegative input before issuing a semantic brand. TypeScript trusts a predicate's annotation even
  when its implementation lies. A nonempty tuple does not make every numeric index defined under
  strict indexed access. `satisfies` is not a universal literal-preservation rule. Security-sensitive
  unknown-field policy and current authorization remain real boundaries. The adopted executable
  example and negative compiler/runtime cases cover these errors.
- **Measurement:** require the promised work, output correctness, error/work counts, comparable tuning,
  limiter and noise analysis. A failed/no-op fast path is not a speedup; one sample is a labeled
  ballpark, and five samples is not a universal proof threshold.
- **Authority:** persistent/autopilot work inherits task-specific grants. AI review, an unattended run
  or a green stack does not authorize human approval, protected-branch merge, publication, deletion,
  provider model changes, external replies or global configuration.
- **Evidence freshness:** preserve valid prior receipts, but recheck changed identity/source/environment.
  Patch-id alone does not preserve a runtime verdict. A later verified stack item cannot bypass an
  unverified prerequisite. Queued, pushed and merged are distinct states.
- **Forensics:** live evaluation/hotfix is mutation even when a source recipe calls itself read-only.
  Supplied traces and source facts never stand in for unobserved runtime behavior.
- **Cleanup/pause:** untracked work is not disposable. No forced worktree/cache sweep or WIP commit
  follows from cleanup/pause guidance. Deletion needs exact scoped authority and ownership evidence.
- **Comments/prose:** retain ambiguous constraints, workarounds, legal/tool directives and suppressions
  until their purpose is established. Clear writing preserves useful technical terms, uncertainty,
  user voice and requested depth; fixed word/diagram quotas are not defaults.
- **Tooling/agents:** reuse local supported tools. Avoid mandatory scripts for small edits, foreign
  worker-policy injection, hardcoded model/cloud choices, automatic judges and dependency bootstrap.
  The earlier [tooling adoption](./pstack-tooling.md) remains separately checked and preserved.

## Check coverage and limits

The review uses repository scope/authority contracts as the acceptance oracle, concrete upstream
counterexamples for TypeScript correctness, and source-to-owner inspection for all 80 methods.
The following frozen challenges are [available as evaluation cases](./evals/pstack-methods-cases.json):

| Challenge | Static conformance finding |
|---|---|
| Supplied competing candidates | Correctness-first rubric; no mandatory agent launch or unjustified graft. |
| Negative duration and lying predicate | Runtime constructor/guard limitations explicitly corrected; executable checks provided. |
| Uncertain technical claim | Preserve “may”, local evidence and unknown production behavior. |
| Old pending catchup call | Include unresolved earlier decisions; do not assign routine agent work to the user. |
| Reverted prior work | Separate prior implementation from current state and unavailable live evidence. |
| Missing video renderer | Storyboard completion cannot become a rendered MP4 claim. |
| Repeated failed patches | Falsify shared dispatch premise before another patch. |
| Fast permission errors | Different/failed work and unmatched environment make the speed claim inconclusive. |
| Stack prerequisite gap | P1 is the verified ceiling; P3 cannot skip P2 or reuse old-base proof by patch-id alone. |
| Explicit pause with dirty/untracked work | Chat checkpoint; no forced commit, stash, file or deletion. |
| Source-only feature map | Separate source-backed recipe from observed runtime coverage and phase authority. |
| Stale formal receipt | A's model pass does not validate changed source B without correspondence/recheck. |

These are **static conformance reviews and frozen future challenges**, not executed provider-agent
behavior tests. No fresh provider evaluation or independent-agent review was run. The local harness's
substring assertions are smoke signals and are not used to claim semantic quality gains or blinding.
Executable integrity, compiler/runtime, routing and lint results are recorded in the validation section.
Live video rendering, bot webhooks, production forensics, actual PR shipping/deletion, application
runtime-map driving and Java/TLC execution were not exercised: those require an actual target,
available tools and effect-specific authority. The catalog's procedures now describe those limits.

# Daily workflows

Generated by `scripts/generate-workflow-guide` from [recipes](./daily-workflows.json) and live skill metadata. Do not hand-edit.

Start with the named entry. The remaining skills are conditional handoffs owned by the caller, not a mandatory sequence. Existing permission and workspace boundaries carry through every step.

For ambiguous requests use `/0-butler`; clear requests can go straight to their entry.

| Task | Start with | Finish when |
|---|---|---|
| Build a bounded change | [/0-implement](../../skills/0-implement/SKILL.md) | The requested behavior works on the tested candidate; relevant checks and review are reconciled. Design and TDD apply when their seams are settled. |
| Reproduce, diagnose, and fix a bug | [/0-diagnosing-bugs](../../skills/0-diagnosing-bugs/SKILL.md) | A reproduction establishes the cause; the accepted fix passes a focused regression check. A diagnosis-only request stops before implementation. |
| Review a supplied change | [/1-code-review](../../skills/1-code-review/SKILL.md) | Findings identify the candidate, location, impact, and supporting evidence. Repair remains a separate outcome. |
| Verify a user journey | [/0-implement](../../skills/0-implement/SKILL.md) | The execution owner records PASS, FAIL, BLOCKED, or NOT RUN for each selected entry point, with candidate identity and evidence surviving teardown. |
| Model and check stateful behavior | [/1-statechart-modeling](../../skills/1-statechart-modeling/SKILL.md) | The model maps to source and each property has its own result, bounds, and gaps. Rendering a chart alone does not establish correctness. |
| Repair known PR blockers | [/1-pr-repair](../../skills/1-pr-repair/SKILL.md) | Known findings and CI blockers have evidence-backed dispositions for the final head. The status watcher reports observations and grants no merge authority. |
